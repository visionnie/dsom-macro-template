## 形态：边操作边录

项目所有者定的：**边操作游戏边录，每点一下记一个节点**，而不是离线在截图上编排。

入口在应用菜单的「录制用例」。开始后拉起游戏，屏幕左上角出现一个黑色小条
显示已记录步数，带「停止」和「撤销」。人正常操作游戏，每次抬手记一个节点。

## 怎么捕获到用户的点击

AutoJs6 里有三条路。**前两条在这台云机上都不通**，是实测出来的，不是推断：

| 途径 | 结论 |
|---|---|
| `events.observeTouch()` | **不可用**。它依赖 root 跑 `getevent` 读 `/dev/input`。root 确实有（见下），但 `getevent -pl` 输出里没有 `ABS_MT_POSITION`，注入点击也收不到事件 |
| 无障碍服务 | **不可用**。只能拿控件级事件，而游戏是 H5 画布，没有控件 |
| **悬浮窗拦截** | **可用**，当前实现走这条 |

**关于 root**：早先查 `which su` 没找到，据此判断"应用侧没有 root"——**这个结论是错的**。
实测 `shell("id", true)` 返回 `uid=0(root)`，AutoJs6 能跑 root 命令。
判断有没有 root 要直接试 root shell，不要看 `su` 在不在 PATH 里。

### 悬浮窗拦截的代价

透明全屏层收到触摸后，游戏就收不到了。所以必须**把这一下转发回去**：

```text
用户点击 -> 捕获层收到 -> 截图 + 记录坐标
         -> 把捕获层设为不可触摸 -> press(x, y) 转发 -> 恢复可触摸
```

实测转发有效：注入点击后游戏界面确实从「首页」跳到了「找游戏」。

## 三个实测踩出来的坑

**1. 窗口创建后不能立刻用。**

从 `threads.start` → `ui.run` 里创建悬浮窗时，`findView(id)` 会**全部返回 null**，
`setSize` / `setPosition` 会抛 `NullPointerException: WindowManager.updateViewLayout
on a null object reference`。必须等窗口 attach 之后（当前用 800ms 定时器）再接线。

**注意时机是分场景的**：在脚本顶层直接创建时，`findView` 立刻可用。
探针里能跑的写法照搬到 `ui.run` 里就会 null，别照搬。

`window.<id>` 那种属性访问更晚才出现（约 600ms），一律用 `findView`。

**2. 布局属性会让 findView 返回 null。**

根节点写 `w`/`h`、子节点写 `w`，`findView` 就找不到控件。
保持根节点带 `id`、不写宽高，尺寸交给 `setSize` 管。

**3. 转发的那一下会落回自己身上。**

只靠 `setTouchable(false)` 挡不住——它走 `ui.run` 是异步的，转发的点击会赶在生效
之前回到捕获层。实测 **3 次点击记成了 5 步**。
必须在触摸回调里**同步**置一个 `forwarding` 标志，转发期间一律吞掉。

## 产出

会话目录 `<outputRoot>/recordings/<sessionId>/`：

```text
01.png  02.png  03.png …   每一步点击前的截图
session.json                节点与截图索引
```

**截图在转发之前拍**：那张图是"点这一下时屏幕长什么样"，
点完再拍到的是下一个界面，将来框锚点就框错了。

`session.json`：

```json
{
  "sessionId": "1789081265612",
  "baseline": { "width": 720, "height": 1280 },
  "nodes": [
    { "id": "step-01", "name": "第 1 步", "type": "tap",
      "rx": 0.5, "ry": 0.4688, "postWaitMs": 3000 }
  ],
  "shots": [
    { "nodeId": "step-01", "path": "…/01.png",
      "deviceWidth": 720, "deviceHeight": 1280, "x": 360, "y": 600 }
  ]
}
```

`postWaitMs` 取自两次点击之间人停顿了多久——停顿本身就是"这一步之后界面要多久"
的真实测量，比拍脑袋填默认值准。只在停顿超过 400ms 时才写。

## 录出来的还不是可回放用例

录制产出的全是 `tap` 死坐标节点。**死坐标换个分辨率就偏**，
项目里反复强调的是锚点定位（`tapImage`）才稳。

所以录完必须有一步**复核**：在每一步的截图上人工框选锚点，把关键步骤升级成
`tapImage`。这一步**还没做**——当前只能把 `session.json` 和截图拉回 PC 手工处理。

框选锚点坚持人工，不自动截取：自动挑锚点是脆的，
把动态背景框进模板后平均像素差 26 就再也匹配不上（见 `RECORDER-RESEARCH.md`）。
