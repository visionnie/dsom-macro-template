## 形态：边操作边录

项目所有者定的：**边操作游戏边录，每点一下记一个节点**，而不是离线在截图上编排。

入口在应用菜单的「录制用例」。开始后拉起游戏，屏幕左上角出现一个黑色小条
显示已记录步数，带「停止」和「撤销」。人正常操作游戏，每次抬手记一个节点。
停止后回到复核页，在那里框锚点、生成用例、回放。

## 怎么捕获到用户的点击

AutoJs6 里有三条路。**前两条在这台云机上都不通**，是实测出来的，不是推断：

| 途径 | 结论 |
|---|---|
| `events.observeTouch()` | **不可用**。它依赖 root 跑 `getevent` 读 `/dev/input`。root 确实有（见下），但 `getevent -pl` 输出里没有 `ABS_MT_POSITION`，注入点击也收不到事件 |
| 无障碍服务 | **不可用**。只能拿控件级事件，而游戏是 H5 画布，没有控件 |
| **悬浮窗拦截** | **可用**，当前实现走这条 |

**关于 root**：早先查 `which su` 没找到，据此判断"应用侧没有 root"——**这个结论是错的**。
实测 `shell("id", true)` 返回 `uid=0(root)`，AutoJs6 能跑 root 命令。
判断有没有 root 要直接试 root shell，不要看 `su` 在不在 PATH 里。

### 悬浮窗拦截的代价

透明全屏层收到触摸后，游戏就收不到了。所以必须**把这一下转发回去**：

```text
用户点击 -> 捕获层收到 -> 截图 + 记录坐标
         -> 把捕获层设为不可触摸 -> press(x, y) 转发 -> 恢复可触摸
```

## 实测踩出来的坑

**1. 窗口创建后不能立刻用。**
从 `threads.start` → `ui.run` 里创建悬浮窗时，`findView(id)` 会**全部返回 null**，
`setSize` / `setPosition` 会抛 `NullPointerException`。必须等窗口 attach 之后
（当前用 800ms 定时器）再接线。在脚本顶层直接创建时 `findView` 立刻可用，别照搬。

**2. 布局属性会让 findView 返回 null。**
根节点写 `w`/`h`、子节点写 `w`，`findView` 就找不到控件。保持根节点带 `id`、不写宽高。

**3. 转发的那一下会落回自己身上。**
只靠 `setTouchable(false)` 挡不住——它走 `ui.run` 是异步的，实测 3 次点击记成 5 步。
必须在触摸回调里**同步**置 `forwarding` 标志。**09-15 实机验证：注入 3 次恰好记 3 步。**

**4. 「停止」的回调跑在 UI 线程，里面不能 sleep。**
否则抛「UI 线程内无法执行阻塞操作」，**整个脚本退出**。session.json 在这之前已存盘，
所以计数看起来都对，只是复核页永远出不来。切前台和等待都放进 `threads.start`。

**5. UI 模式下别用 `app.launchPackage` 把自己切回前台。**
开发路径下宿主包是 AutoJs6，拉起来的是它的文件列表；脚本页与之同处一个任务栈，
约 1 秒后被销毁，脚本结束。工作线程被中断，runtime 的 `catch` 捕获不到，
`result.json` 停在 `status: "running"` 且没有 `error`。
改用 `moveTaskToFront`，见 `src/core/foreground-autojs.js`。**这个坑不只影响录制器**——
从菜单跑任何 `captureAfterLaunch` 任务都会踩到，runtime 已一并改掉。

## 复核与框选锚点

复核页列出每一步，点一步进入框选页：截图按比例铺在画布上，红点是当时点下去的位置。

- **升级找图**：在截图上拖一个框。框住的区域裁成 `anchors/<节点id>.png`，
  节点改写为 `tapImage`；点击位置不必在框里，按 `offset` 从锚点中心挪回原位
- **保持坐标**：已升级的步骤还原为 `tap`（从截图记录里的原始像素坐标算回来）
- **删除此步**：只从会话里摘掉，截图文件留在磁盘上

框小于 16x16 像素直接拒绝。锚点坚持人工框，不自动截取：
自动挑会把动态背景框进去，平均像素差 26 就再也匹配不上。

换算逻辑在 `src/core/case/recorded-case-autojs.js`，纯函数、不碰设备全局对象，
可以在 PC 上用 Node 验证。偏移的中心算法与 `screen.findTemplate` 一致（左上角 + floor(宽/2)）。

## 产出

会话目录 `<outputRoot>/recordings/<sessionId>/`：

```text
01.png  02.png …        每一步点击前的截图（转发之前拍，框锚点要的是点下去那一刻的画面）
session.json            节点、截图索引、基线、各步锚点框
anchors/step-01.png …   框出来的锚点图
case.json               「生成用例」写出的可回放用例
```

`case.json` 是标准的 `nodes` 用例，多一个 `assetBase: "case"`：锚点相对用例文件解析，
因为打包后的 `assets/` 是只读的（见 `CASE-MVP.md`）。

**基线在停止那一刻定下，取第一步截图的尺寸**，随会话保存。复核页是竖屏，
若之后存盘时实时读 `device`，基线会被悄悄改掉。录制中途屏幕方向变过的会话**拒绝生成用例**，
报出是哪几步——各步归一化坐标按各自尺寸算的，混进一条用例会静默点偏。

`postWaitMs` 取自两次点击之间人停顿了多久，只在超过 400ms 时才写。

## 回放

「生成并回放」生成 `case.json` 后用一个临时任务交给 runtime 跑，
与业务用例同样先启动游戏、后申请截图权限。任务 id 是 `recorded:<会话 id>`，
结果落在 `<outputRoot>/recorded_<会话 id>/<runId>/`——**任务 id 会被当成目录名，
runtime 会把冒号一类的字符换成下划线**，否则 `adb pull` 在 Windows 上根本建不了这个文件，
而设备侧不会报任何错。
「运行记录」页能看到。临时任务不进任务登记表：录制用例是设备上现生成的数据，不是仓库代码。

这个临时任务由 `src/core/recorded-task-autojs.js` 造，**手动回放与常驻调度共用同一份**——
两处各造一份的话，手动回放通过、到点自己跑却换了套前置开关，差异只会在无人值守的夜里暴露。

## 怎么验证

录制只能从菜单进（`task.txt` 存在时会跳过菜单直接跑任务）。用 adb 驱动：
`uiautomator dump` 找「录制用例」「开始录制」的坐标点击，授权后注入固定次数的点击，
点「停止」(45,60)，再数 `session.json` 里的节点——比看计数可靠。
框选用 `input swipe`，坐标按画布位置与缩放比例从截图像素换算。

**设备上装有自动按键精灵（com.jshd.auto）**。它在跑任务时，它的点击也会被录进来，
我们的捕获层也会吞掉它的点击。验证前先确认它没在跑。
