# 项目说明 - PROJECT.md

## 一句话

`dsom-macro-template` 是可复用的 AutoJs6 Android 游戏自动化模板：每个游戏独立建仓库，共享运行时和工程结构，只替换游戏配置、视觉素材与业务任务。

## 为什么这样做

公司会持续增加新游戏，每款游戏的页面、坐标和业务流程不同，但设备接入、截图、找图、OCR、动作、等待、日志、失败留证和打包方式高度重复。

直接复制已有游戏会把旧包名、坐标、设备信息和业务历史带入新项目。因此本项目明确分为通用层与游戏层，并提供脚本生成干净项目。

## 技术边界

- 运行环境：AutoJs6。
- 设备：Android 真机、模拟器、云机。
- 核心输入：MediaProjection 截图、找图、OCR、像素判断。
- 核心动作：无障碍点击、滑动和手势。
- ADB：仅用于开发调试和文件传输，业务任务不能依赖 ADB。
- 输出：任务日志、结构化结果、阶段截图和失败截图。

## 目录边界

```text
src/config/   当前游戏的项目级配置
src/core/     所有游戏可复用的运行时
src/core/case 可回放用例的结构契约，见 .docs/CASE-SCHEMA.md
src/entry/    AutoJs6 单文件打包入口
src/tasks/    当前游戏的业务任务
src/assets/   当前游戏的找图素材
.docs/script/ 构建、检查和新项目生成脚本
dist/         生成的 AutoJs6 单文件，不提交 Git
```

通用层禁止出现具体游戏包名、页面名称、业务坐标和颜色阈值。一个能力至少被三个任务稳定复用后，再考虑抽取到 `src/core/`。

## 标准接入流程

```text
创建新游戏项目
-> 填写包名和屏幕配置
-> 运行环境检查
-> 运行游戏启动检查
-> 截图标定页面状态
-> 新建独立业务任务
-> 实机验证失败留证
-> 稳定能力按需抽取到通用层
```

## 新游戏复用

```powershell
node .\.docs\script\create-game-project.js `
  --target F:\Git\AI\dsom-macro-new-game `
  --id new-game `
  --name "新游戏" `
  --package com.company.game
```

生成器只复制通用骨架、环境检查和任务模板，不复制当前游戏后续新增的业务任务、素材或设备信息。

## 安全原则

- 页面无法确认时停止，不盲点。
- 点击付费、购买、删除等高风险操作前必须有明确状态判断和安全上限。
- 循环必须设置次数或时间上限。
- 禁止提交账号、口令、云机地址和带敏感信息的截图。
